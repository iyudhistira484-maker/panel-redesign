# Keputusan penggantian Pterodactyl

Target: Relay mengambil alih fungsi Panel Pterodactyl; Wings tetap menjalankan workload. **Belum siap cutover produksi atau diklaim setara penuh.** Bukti staging tidak otomatis berlaku pada workload produksi, terutama untuk penulisan aktif, operasi destruktif, dan integrasi eksternal.

| Area | Bukti yang tersedia | Syarat sebelum dinyatakan setara |
| --- | --- | --- |
| Akun dan operasi harian | Login, reset, TOTP, inventaris, power, statistik, console dan sebagian file diuji di staging | Jalankan skenario harian kandidat; verifikasi SFTP (password dan key), operasi file yang belum terbukti, dan izin lintas pengguna |
| Siklus hidup dan integrasi | Application API untuk inventaris, create/delete dan rekonsiliasi fixture; Nodeactyl untuk cakupan Client yang diuji | Uji integrasi yang benar-benar dipakai, startup/image/reinstall, secondary allocation, dan egg representatif. Jangan perluas operasi destruktif sampai batas cakupannya diverifikasi |
| Penyimpanan dan otomatisasi | Restore database panel dan volume Wings lintas runner; rollback ke Pterodactyl untuk server adopsi | Uji backup per-server lokal/S3, database milik workload, jadwal, subuser, retensi, dan pemulihan kunci produksi bila fitur itu dipakai |
| Cutover dan rollback | Fixture adopsi kembali terlihat di Pterodactyl; fixture buatan Relay tidak otomatis muncul di sana | Inventaris kedua panel harus direkonsiliasi; tetapkan satu panel yang boleh menulis, batas keputusan rollback, dan tindakan eksplisit untuk entitas baru serta perubahan pasca-checkpoint |

## Urutan kerja

1. **Lulus di staging:** [uji HTTP lintas runner](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45657665682) membuktikan baca checkpoint, tulis, dan baca ulang setelah restart dari client lain di jaringan staging. Bukti terbatas pada fixture HTTP sintetis.
2. Pilih satu workload staging representatif dan buat daftar fitur yang digunakan berdasarkan [inventaris Client](../stage-0/api-client.md), [Application](../stage-0/api-application.md), dan [checklist upstream](../stage-0/parity.md). Tandai tiap fitur **terbukti**, **belum diuji**, **belum tersedia**, atau **tidak digunakan**. Jangan menandai kemampuan Relay hanya karena endpoint upstream tercatat.
3. Uji migrasi dan rollback workload itu sebelum menjadwalkan produksi. Catat batas downtime/kehilangan data, langkah penerapan ulang pencabutan akses, penanggung jawab, dan mekanisme observasi layanan. Jalankan backup/restore dan rollback sebagai latihan operasi, bukan sekadar proses CI hijau.
4. Jika semua fitur yang diperlukan lulus dan pemilik menyetujui, pilot produksi satu server berisiko rendah; Pterodactyl tetap tersedia untuk rollback. Perlu persetujuan eksplisit sebelum rollout. Migrasi bertahap setelah pilot stabil. Untuk mengklaim **setara penuh**, tuntaskan pula fitur upstream di luar cakupan pilot atau dokumentasikan pengecualiannya.

## Audit dan bukti terbaru

- [Foundation 45716625356](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45716625356): Pterodactyl staging → Relay → tulis record lewat HTTP → Pterodactyl. Record tetap terbaca; UUID, ID container, waktu mulai dan checksum startup tidak berubah. Pergantian control plane **1.495 ms** dan rollback **1.517 ms**. Tiga probe HTTP sukses pada masing-masing perpindahan, tanpa kegagalan teramati; itu bukan bukti downtime absolut nol. [Foundation 45716638643](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45716638643) juga lulus setelah perapian lint.
- [Audit per rute](api-parity-audit.md) membandingkan inventaris upstream dengan registrasi Relay. Ini antrian kerja yang bisa diuji otomatis, bukan sertifikasi perilaku atau pengganti audit UI dan operasional.
- [Foundation 45718547786](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45718547786): `GET /api/client/permissions` mengembalikan katalog 40 izin yang identik dengan respons Panel v1.15.2 untuk bearer Client yang valid; tanpa autentikasi ditolak `401`. Ini katalog metadata, bukan implementasi atau pemberian 40 izin.
- [Off-host 45717418047](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45717418047): regresi restore lintas runner lulus dengan kunci independen setelah pengulangan job yang terkena batas pull Docker Hub. Data HTTP pasca-restore masih bertahan setelah restart.
- [Foundation 45719375388](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45719375388): `GET /api/client/account` cocok dengan respons Pterodactyl untuk akun dengan pemetaan profil yang diverifikasi di fixture; anonim mendapat `401` dan akun tanpa pemetaan mendapat `404`. ID upstream hanya metadata; otorisasi tetap mengikuti UUID dan status akun Relay. Belum ada provisioning otomatis profil produksi, dukungan profil Relay-only, atau mutasi email/password pada jalur ini.
- [Foundation 45720441615](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45720441615): OpenSSH SFTP pada Wings nyata dapat mengambil byte yang sama dengan pembacaan Wings; upaya upload tidak membuat file. Password salah, node salah, target node lain, origin browser lain, dan metode public key ditolak. Cakupan hanya **pemilik dengan password dan tanpa TOTP, baca-saja**, aktif hanya pada harness legacy-panel disposable. Belum termasuk public key, TOTP, subuser, write, atau penerapan SFTP di produksi.
- [Foundation 45725423035](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45725423035): OpenSSH dengan kunci Ed25519 subuser ditolak sebelum izin file diberikan, membaca byte identik setelah mendapat `file.sftp`, `file.read`, dan `file.read-content`, lalu koneksi **baru** kembali ditolak saat izin itu dicabut tanpa menghapus grant lain. Relay hanya menyimpan fingerprint publik. Ini masih baca-saja, staging disposable, tanpa TOTP, dan registrasi kunci melalui fixture; pencabutan sesi SFTP yang sudah terhubung, operasi tulis, dan API manajemen SSH key belum diuji/tersedia dalam cakupan ini.
- [Foundation 45726259743](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45726259743): sesi akun yang sudah terautentikasi dapat tambah, daftar, dan hapus kunci publik Ed25519 miliknya. API bearer dan origin asing ditolak, duplikat ditolak, dan akun lain tidak bisa melihat atau menghapus kunci. Kunci yang ditambahkan lewat API dipakai dalam kontrak OpenSSH. Ini bukan paritas penuh Pterodactyl (sesi saja, akun terpetakan, satu format kunci).
- [Foundation 45726822275](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45726822275): uji OpenSSH nyata membuktikan koneksi **baru** ditolak setelah grant dicabut, tetapi koneksi **yang sudah aktif** masih mampu membaca file. CI hijau karena tes mereproduksi batas Wings ini, bukan karena pencabutan aktif lulus. Tahan write/produksi sampai tersedia pemutusan sesi atau otorisasi per operasi yang lolos uji. Empat kelompok lain tidak ditutup oleh pekerjaan ini.
- [Job legacy-panel 139603976521](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45728397340/job/139603976521): **pencabutan sesi aktif lulus untuk Wings staging yang dipatch**. OpenSSH membaca sebelum pencabutan; sesudahnya koneksi baru ditolak dan koneksi lama tidak lagi bisa membaca. Pemutusan teramati pada pemeriksaan klien sekitar 5 detik; bukan jaminan pencabutan instan. Wings bawaan tidak memiliki perbaikan ini. SFTP tetap baca-saja dan disposable. Sebelum write atau produksi, uji pencabutan karena penghapusan kunci, perubahan password/TOTP, kehilangan callback, kapasitas callback, serta pastikan binary yang dipatch benar-benar dipakai. Perubahan yang sudah selesai sebelum pemeriksaan ulang tidak dibatalkan.
- [Foundation 45730197985](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45730197985): OpenSSH/Wings staging membuktikan sesi aktif berhenti membaca pada lima kondisi: grant dicabut, hash password dan versi autentikasi berubah, TOTP diaktifkan, callback Relay terputus, dan kunci dihapus lewat API. Mutasi password/TOTP menggunakan perubahan state fixture, bukan uji UI/endpoint pengaturan akun. Hasil terlihat sekitar 5 detik pada probe klien dan tidak membatalkan operasi yang selesai sebelumnya.
- [Foundation 45730824444](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45730824444): subuser Ed25519 dengan grant eksplisit berhasil membuat, menimpa, dan menghapus file melalui OpenSSH. Byte/ketiadaan file diverifikasi dari Wings; percobaan tulis oleh akun baca-saja tidak membuat file. Pemeriksaan ulang lease juga menolak perubahan himpunan izin yang dikembalikan. Tetap hanya harness staging dengan Wings yang dipatch; belum menetapkan kesiapan produksi, dukungan SFTP penuh, atau penutupan empat kelompok penggantian lain.
- [Foundation 45732947101](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45732947101): pemilik menambahkan akun Relay yang sudah ada, melihat daftar, mengatur mode SFTP, dan menghapus akses dari Chromium melalui API native `/api/v1/servers/:id/subusers`. Bukan undangan email atau API kompatibilitas Pterodactyl. Subuser/pihak luar tidak bisa mengubah izin. Pada OpenSSH dan Wings staging, pemilik menurunkan write ke read lewat API: sesi lama ditutup; sesi baru dapat membaca tetapi tidak dapat mengunggah, dan server tetangga tidak berubah. Mode SFTP mengubah grant file terkait; nonaktifkan SFTP tidak menghapus hak baca file panel yang sudah ada. Akses tulis masih memerlukan fixture staging dan Wings yang dipatch. Pekerjaan berikutnya: backup lokal per server.
- [Foundation 45734819313](https://github.com/iyudhistira484-maker/panel-redesign/actions/runs/45734819313): kontrak backup lokal pada Wings nyata lulus untuk fixture offline. Relay menerima callback create dan restore hanya untuk ID/tahap yang diharapkan. Unduhan bertoken sekali pakai cocok dengan ukuran dan checksum Wings, replay ditolak, restore backup tak ditemukan tidak mengubah file, dan restore valid mengembalikan byte checkpoint tanpa truncate. Ini pembuktian protokol staging, **bukan** API/UI backup pengguna atau penyimpanan metadata persisten. Berikutnya: metadata/receipt yang tahan restart, kepemilikan dan kuota, API pengguna, serta delete/lock/reconcile yang diuji sebelum S3/jadwal.
