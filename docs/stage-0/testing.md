# Test strategy and CI gates

- Every PR: pinned lockfile/toolchain, format/lint/strict types, unit tests, dependency audit, secret scan, build and OpenAPI drift check; use least-privilege CI, no secrets for untrusted contributions. Require checks before merge once configured.
- Integration: disposable SQL + Redis test instances, reversible migration up/down with data-loss assertions, transactional jobs and restart/deduplication tests. Test policy matrix per permission and resource type. Test indexed filters, API status/pagination and request validation.
- Real Wings qualification: disposable Linux VM with Docker (never share a production or general CI host socket), pinned Wings candidate image digest, private bridge and controlled egress, staging TLS, tiny disposable approved egg and local object-store/S3 test endpoint. Run Panel/Wings as separate containers; give Docker access only to Wings inside the sacrificial VM. Run upstream Panel as a reference with separate data and volumes. Record version/digest and capture redacted wire fixtures for both directions. Teardown VM after suite. No production network route.
- Wings required cases: bootstrap paginated adoption without recreating containers; bad auth/wrong node; create/install/report/start/stop/reinstall/delete; command and live stats/console with token refresh/revoke; file read/write/archive/pull/upload/download; SFTP password and SSH; local and S3 backup create/restore/delete; two isolated nodes for transfer, cancel/failure and successful reconciliation; retry callbacks and daemon reboot. Assert side effects and payload shapes, not status alone.
- Import: sanitized dump from identified upstream version, fixture encrypted values + bcrypt/TOTP examples, unknown schema and corrupt orphans, dry-run no writes, two identical imports, interrupted import, restore drill, grant comparison. Stage 10 additionally needs approved real-data copy and real verification report.
- Playwright: login/reset/2FA, provision server, console and power, files/SFTP UI, backups, schedules and subusers, remaining admin/client flows. English and Indonesian; keyboard/focus/manual contrast plus axe and responsive widths. Verify emails in common clients. Stage 1 sets size/time budgets using reproducible runner and profiles.
- Stage 13: at least 50 simulated servers across 5 simulated nodes with real-Wings spot checks; assert polling/queue caps, latency/error budgets agreed at Stage 1, graceful outages/recovery, backup/restore and key rotation, privacy leak scenarios and final accessibility audit.

No test suite has run against a real node here: Docker CLI/socket not available. This blocks runtime protocol sign-off, not review of the proposal. No code, CI config or test fixtures until approval.
