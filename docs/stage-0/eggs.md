# Eggs and nests

Panel `EggParserService`, `Sharing/Egg{Importer,UpdateImporter,Exporter}Service`, `EggConfigurationService` and the bundled seed eggs are the source baseline. `meta.version` allows PTDL_v1 and PTDL_v2; v1 maps `images` or fallback `image` into an image-name-to-reference map and assigns variable `field_type=text`. Upstream exporter emits v2 only. Proposed v1 export is an explicit compatibility conversion: refuse loss of v2-only semantics unless the operator explicitly requests a lossy export and sees the differences.

Preserve name/author/description, update URL (metadata only), features, image labels/references, file denylist, startup interpolation, `config.files/startup/logs/stop`, and `scripts.installation.{script,container,entrypoint}`. Nested config can be JSON encoded as strings; verify parser type, matching/replacement and completion/stop behavior in Wings, not with generic string replacement. Preserve variable name, description, env key, default, user view/edit flags and Laravel validation rules. Validate at assignment; unsupported rules block qualification rather than being ignored. Preserve database inheritance (`config_from`, copied install scripts), materialize effective values on export; nests are catalog groupings, not portable egg dependencies.

Acceptance: import real v1/v2 examples unchanged; compare normalized round trips and installation/start/stop behavior (including inherited configurations and multiple images); test malformed documents, duplicate env keys, complex rule syntax and permissions. Install scripts are privileged admin-supplied executable artifacts, never evaluated by Panel; keep original bytes and require admin review before doing anything on the isolated node.
