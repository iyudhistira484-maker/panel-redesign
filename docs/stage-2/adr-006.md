# ADR 006 — Sesi buram dan kredensial identitas

**Status:** Diimplementasikan untuk staging; belum dikualifikasi di MySQL nyata.

Gunakan sesi buram yang verifier-nya disimpan di MySQL. Dibanding JWT sesi, logout dan perubahan faktor dapat mencabut sesi langsung tanpa denylist eksternal. Biayanya satu pembacaan SQL per permintaan dan pembersihan periodik; jangan pindah ke Redis sampai perilaku pencabutan setara diuji. Kunci akses akun tidak meminjam izin administrator. Pisahkan pepper verifier dan kunci enkripsi TOTP dari database. Jangan gunakan ulang APP_KEY lama.

Untuk drill rotasi, hentikan operasi identitas dan cadangkan skema + kunci lama secara terpisah. Untuk TOTP, siapkan alat offline tervalidasi yang mendekripsi tiap record sesuai versi/AAD, menulis ulang dengan kunci baru dan memverifikasi hasil sebelum beralih. Pertahankan backup/kunci lama sampai rollback tidak lagi diperlukan. Untuk pepper, siapkan komunikasi dan jalur pemulihan TOTP, cabut sesi/reset/API key, susun penerbitan kembali recovery code, ganti pepper, lalu verifikasi sesi lama gagal dan akun baru tetap bisa login. Belum ada alat rotasi otomatis; jangan lakukan perubahan kunci pada data yang belum dicadangkan.
